## Major
1. Section 0 / PR B gate is stale. CLAUDE.md "Standing permissions" (merged #411) says #386's "nothing on the MacBook" is superseded: `--bench` may run on the M3 with no fresh offer when (a) he is not using the machine (his word overrides), (b) `pmset -g ps` prints AC Power, (c) nothing compiled/tested for 5 min and no process holds a core, (d) all runs recorded as they came out, power state in the row. It also allows closing his apps for a measurement (say afterwards what was closed). Replace "needs the owner's own offer" with this checklist. Caveat: a fullscreen, mouse-captured 30-minute run is a heavier takeover than a headless bench; condition (a) is still his to assert, so the executor should confirm he is away (one line via the contact session), not ask permission for the action. Plan's `pmset -g therm` also should be `pmset -g ps` for the AC test.
2. What the numbers mean needs to be stated per mode, not once. Present-to-present on the app thread: under Fifo (displaySync true, drawable pool 3, nextDrawable blocks) the gap is gated by the compositor and is close to a real cadence measure; under Immediate (what the M3 runs by default; no Mailbox on Metal) at 1000+ FPS the gap says only that the loop did not hitch, nothing about which frames reached a refresh. wgpu 30 exposes no presentation feedback; MTLDrawable presentedTime needs as_hal + unsafe. Plan rightly defers that, but it should put "Immediate rows show app-thread hitches only; Fifo rows are the closest to the glass" in the footnote and in the report to the owner, and propose the on-glass follow-up issue explicitly if both are clean. Also record the acquire wait (time inside get_current_texture) separately from the gap if cheap, since a block there is the likely Fifo-visible stutter.
3. Background-load control is weaker than ⁸⁹ shows. Load average < 1.5 would have passed the four-agent night. Add: an A-off control run repeated at the start and the end of the session (drift check), print frames-per-run in every row, and treat a config's run as suspect if its frame count differs from the median by more than a stated margin. Verdict rule (|median diff| > max spread over 3 runs) is weak; keep it, but label it chosen, and give all runs.
